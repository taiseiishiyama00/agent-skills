# YouTube Shorts制作

> この文書は派生手順書であり、Short要求の正本ではない。対象チャンネルの `channels/<channel-id>/video-standard.md` にある要求IDを、縦動画の制作と検査へ詳細化する。

Short台本の保存、Google Docsでの共同編集、ユーザーコメントの反映、`source/scripts/short.md` への同期は [script-collaboration.md](script-collaboration.md) に従う。

## 事実と公式仕様

- Shortの最大尺、解像度、関連動画、リンク、Content IDなど変更され得るYouTube仕様は、作業時にYouTube公式ヘルプで再確認する。
- チャンネルの数値、目標尺、安全域、余韻時間、字幕制約は対象チャンネルの `video-standard.md` を正本とし、pipelineの設定は機械実装として一致させる。
- Shortsの説明欄やコメント欄のURLを主要導線にしない。横動画への導線にはYouTube Studioの「関連動画」を使う。
- 固定ピクセルの安全域をYouTube公式値として断定しない。実機UIの変動を前提に、チャンネル設定と限定公開後の表示を確認する。

主な公式確認先:

- https://support.google.com/youtube/answer/15424877?hl=ja
- https://support.google.com/youtube/answer/10059070?hl=ja
- https://support.google.com/youtube/answer/16215842?hl=ja
- https://support.google.com/youtube/answer/14075157?hl=ja
- https://support.google.com/youtube/answer/13748639?hl=ja

## 台本

- 横動画のGoogle Doc `long` を、横動画と呼び込み用Shortの共通発話正本とする。
- 横動画台本の先頭から、コントとハンドリングにある強い問題提起までを、句読点、話者、ト書き、章境界、発話順ごと完全コピーする。横動画のオープニングインサートと、それ以降の本編は含めない。
- コピー区間の後に、チャンネルprofileで定義した解説役の「詳しくは本編動画で解説しています。」、進行役の「ぜひ関連動画から見てください。」という役割のCTAだけを追加する。
- 確定した `long` から生成したGoogle Doc `short` は人間確認用ミラー、`short.md` は発話・TTS・字幕・映像設計へ渡す制作入力とする。どちらにも独立したShort台本を書かない。
- Short向けにコピー区間を要約、言い換え、短縮、並べ替え、フック強化しない。最大尺を超える場合も自動で内容を削らない。
- `long` のコピー元がコメント反映中、または未確定なら、ShortのTTS、字幕、映像実装へ進まない。
- コピー区間に事実確認済みの内容との矛盾や必要な留保の欠落が見つかった場合は、生成後のShortだけを直さず、Google Doc `long` の台本修正へ戻す。
- 冒頭のコント、ハンドリング、問題提起の順序と演出意図を横動画から保ち、Short固有のロゴや挨拶を前置きしない。
- CTAは実際に設定するYouTubeの「関連動画」導線と一致させる。
- 最後の台詞を言い切った後、設定された余韻時間だけCTA画面を保持する。

## 音声と字幕

- 会話の抑揚を保つため、Short台本は可能な範囲で一つの連続音声としてTTSへ渡す。
- 有料生成前にdry-runで話者、区間、リクエスト数を確認する。
- Gemini TTS音声は横動画と同じく通常1.25倍、`id: skit` のコント章1.5倍とし、Shortだから速度を変えない。
- 話速を変換するときは、発話、字幕、場面切替の時刻を同じ比率で変換する。
- Short台本から意味チャンクを先に作り、MFAで各チャンクの語頭時刻へ合わせる。
- 字幕は常に一つのcueだけを表示し、行数と1行文字数はチャンネル設定に従う。
- 句読点だけでなく、話題転換、疑問、重要な数字の前後でチャンクを分ける。
- スマートフォンの無音視聴でも要点が分かり、音ありでは発話と字幕の語頭が一致することを確認する。

## 映像と素材

- 横動画の正式アバター、テーマ色、写真、図、リファレンス、共通BGM・効果音を先に再利用する。
- チャンネルの正式な登場人物を、台本上の意図がないのに汎用シルエットや代替人物へ置き換えない。
- 横長素材を無理に拡大せず、縦画面で情報が欠ける場合は別クロップ、コード生成図、Short固有素材を用意する。
- 話題固有素材は作品側、複数作品で使う素材はrenderer側へ置く。
- 企業、製品、組織が主題なら公式一次ソースのロゴ、アイコン、画面を検討し、出典URLと権利区分を登録する。
- 安全域、見出し、リファレンス、人物、字幕、背景は共通レイアウトへ集約し、作品側で人物や字幕位置を場当たり的に上書きしない。
- 発話ごとの説明ビジュアルは独立したSequenceにし、次の発話へ不要な前場面を残さない。
- 意味の異なるvisual IDへ同じ汎用図解を使い回さない。
- 発話ごとに `semanticBeat`、`visualStrategy`、`assetIds`、`motion`、`sfxCue` を決める。質問の発話で本編の答えを先出ししない。
- 因果・時間変化・物理的な比喩は縦画面でもアニメーションを優先し、人物・場所・商品など具体物は登録済み外部写真・動画を使う。
- 写真は縦向けクロップを作り、パン、ズーム、マスクなどの動きを付ける。汎用カードや静止テキストだけで画面を埋めない。
- 列挙は縦方向と順次表示を基本にし、横並びで意味構造を潰さない。
- 動きの切替へ権利確認済みの効果音を同期し、Short全編MP4で画像・動き・意味順・同期を検査する。
- 重要なオブジェクトは字幕cueに合わせて更新し、長時間の完全静止を避ける。
- Shortは縦尺の全編MP4を作り、確認対象はパイプラインが動画内時刻へ対応付ける。音声単体、静止画、contact sheet、motion clipを別の承認成果物にしない。

## Shortサムネイル

1. Short本編と横動画の内容を確認し、誤解なく最大の関心を生む一つのフックを決める。
2. 主要な数字または結果を最も大きくし、正確性に必要な留保を短い補助ラベルで残す。
3. チャンネルの正式な人物・表情素材を使い、理由のないシルエットや汎用人物を使わない。
4. 縦長サムネイルをrendererの再現可能なCompositionとして実装する。
5. CLIのサムネイル検証を通る画像形式、寸法、容量で書き出す。
6. 実寸に加え、YouTube Studio一覧相当の約180×320表示で、主フックと人物が判別できるか確認する。
7. Google Drive側の投稿設定へサムネイルパスを記録し、`youtube validate` 後に `youtube thumbnail ... --confirm-upload` で設定する。
8. 設定成功だけで完了にせず、キャッシュを避けてYouTube画像配信先の標準サイズと縮小サイズを再取得し、実画像を目視確認する。

Studioアプリで複数動画が一様に灰色の場合は、設定漏れと即断しない。投稿状態、画像配信先、別回線またはアプリ再起動を切り分ける。配信先が新画像を返すなら再アップロードを繰り返さない。

## 公開前チェック

- 横動画の全segment MP4と、初期化済みShortの全編MP4が最新で、各segmentを人が明示承認している。
- 投稿用の全編MP4が最終承認済みである。承認済みレビューMP4と投稿用ファイルが同一hashなら、同じ動画への重複承認は求めない。
- Google Doc `long` のコピー元、生成したGoogle Doc `short`、同期済み `short.md`、TTS・字幕・映像設計の発話内容が一致している。
- Google Doc上のユーザーコメントが反映済み、または要確認として未解決のまま明示されている。
- 冒頭が横動画と同じコントで始まり、ハンドリングの問題提起まで順序が変わっていない。
- 右端と下部に重要な数字、顔、字幕、CTAがない。
- 字幕の切れ、はみ出し、低コントラストがない。
- 音声と字幕の語頭が合っている。
- 音量、声質、テンポが途中で不自然に変わらない。
- 画面を止めたまま説明している区間がない。
- Shortが答えを先出しせず、問題提起から本編への期待をつないでいる。
- 終盤に横動画へのCTAがあり、公開時に関連動画を設定する。
- 素材の権利、出典、リファレンスIDが台帳と一致する。
- 限定公開後、利用可能なスマートフォン実機とデスクトップで表示を確認する。

## 公開後

- 視聴を選択した割合とスワイプ割合を冒頭フックの評価に使う。
- 平均視聴時間、平均再生率、離脱位置をShort台本と字幕cueへ対応付ける。
- 関連動画への遷移と横動画冒頭の離脱を合わせて確認する。
- 改善をShort台本、共通設定、共通コンポーネント、作品固有演出のどこへ反映するか分ける。
