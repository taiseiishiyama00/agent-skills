# 動画品質レビュー手順書

> この文書は派生手順書であり、品質ゴールの正本ではない。対象チャンネルの `channels/<channel-id>/output-rules.md` にある要求IDを、MP4の再生検査へ詳細化する。

## 入力

- 対象チャンネルID
- 正本IDと版
- 対象作品ID
- 対象成果物の絶対パス、種別、SHA-256
- segmentの場合はsegment ID、開始・終了フレーム、対応章
- 自動検証結果
- 今回適用する要求ID

入力が不足する場合は合格にせず、先にpipelineのreview taskまたはstatusを更新する。

## 再現可能な検査条件

1. MP4を変換せず、実際の解像度、fps、音声付き、通常速度で先頭から末尾まで再生する。
2. 横動画は実寸表示と幅360px相当の縮小表示、Shortは実寸表示と約180×320表示で確認する。
3. 音声ありで同期と音質を確認し、音声なしでも字幕と映像から主題を追えるか確認する。
4. segment境界の前後を連続再生し、姿勢、背景、字幕、音声、BGMのジャンプを確認する。
5. 自動検証済みの項目も、MP4上で明らかな反証があれば不合格に戻す。

同一hash、同一正本版、同一要求ID集合の成果物を再検査する場合は、入力条件が同じであることを確認して同じ判定基準を使う。hashまたは正本版が変わった場合は以前の判定を再利用しない。

## 要求ID別の観点

### 内容と構成

- `ITTAN-LONG-001`: コント、ハンドリング、オープニングインサート、オープニング、本編、影響、行動、まとめ、12秒エンディングの順序と欠落を確認する。
- `ITTAN-LONG-002`: コントがニュースの答えを先出しせず、TVへ引く接続と本題の問いが成立するか確認する。
- `ITTAN-LONG-005`: 行動が最低2つあり、まとめが冒頭の問いへ答えているか確認する。
- `ITTAN-SHORT-001`: 横動画冒頭との意味・台詞・順序が一致し、Short固有の前置きがないか確認する。

### 音声と字幕

- `ITTAN-AUDIO-001`: 発話速度が途中で急変せず、口の動き、字幕、場面切替、効果音が音声と一致するか確認する。
- `ITTAN-AUDIO-002`: 章間で音量・声質が跳ばず、クリップ、破裂音、欠落、不自然な継ぎ目がないか確認する。
- `ITTAN-CAPTION-001`: cueが対応語頭と一致し、同時表示、切れ、はみ出し、低コントラストがないか確認する。

### 映像と素材

- `ITTAN-VISUAL-001`: 台詞の意味順どおりに映像が更新され、質問時に答えを先出しせず、前場面が残らないか確認する。
- `ITTAN-VISUAL-002`: 具体物に適切な写真・動画があり、画像と図解が静止貼り付けやPowerPoint風カードの反復になっていないか確認する。
- `ITTAN-VISUAL-003`: 人物、接点、重心、足運び、見切れ、重なり、入退場、縦横構図を確認する。
- `ITTAN-VISUAL-004`: BGM、ジングル、効果音が意味のある動きと同期し、台詞を妨げていないか確認する。
- `ITTAN-ASSET-001`: 画面上の出典IDと台帳の素材・権利・用途が一致するか確認する。

### 出力と公開

- `ITTAN-OUTPUT-002`: オープニング、章タイトル、エンディングの時間が設計と一致し、エンディングが12秒あるか確認する。
- `ITTAN-OUTPUT-003`: 終了画面の案内枠と実要素の位置・開始・終了が一致するか確認する。
- `ITTAN-QA-001`: 黒画面、欠落、無音、意図しない静止、仮素材、デバッグ表示、segment境界のジャンプがないか確認する。
- `ITTAN-PUBLISH-001`: 配信された動画、サムネイル、終了画面、関連動画が承認済み状態と一致するか確認する。

## 判定

要求IDごとに次を記録する。

```json
{
  "standardId": "ITTAN-VIDEO-STANDARD",
  "standardVersion": "1.0.0",
  "artifactSha256": "<sha256>",
  "requirementId": "ITTAN-VISUAL-001",
  "result": "pass | fail | not-applicable",
  "evidence": "<時刻、画面、測定値、または確認内容>",
  "issue": "<fail時の再現可能な問題説明>",
  "reviewerRole": "non-implementer"
}
```

- `pass`: 合格状態を確認できた。
- `fail`: 1件以上の反証がある。時刻と現象を記録する。
- `not-applicable`: 正本上で対象外と判断でき、理由を記録した。

未確認、証拠なし、判断不能は `pass` にしない。blocker、major、または明白な品質不足が1件でもあれば成果物全体を人へ渡さない。

## 再検査

- 局所修正では変更segmentの新hashだけを再検査する。
- 共通部品、全体構成、音声、字幕時刻、共通素材、正本版の変更では全segmentを再検査する。
- 修正後は同じ要求IDと同じ観点を使い、以前のfailが消え、新しい問題が発生していないことを確認する。
