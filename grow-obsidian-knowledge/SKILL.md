# Grow Obsidian Knowledge

## 目的

作業中に得たコンテキストを、次の作業で再利用できる知識として Obsidian vault に蓄積する。ノートを増やすことではなく、既存ノートを更新・統合して知識を育てることを優先する。

- vault の正本は GitHub の `taiseiishiyama00/obsidian-knowledge`、ローカルは通常 `$HOME/repos/obsidian-knowledge`。
- vault の構成、ノートの記法、書かないものは vault の `README.md` を正本とし、このスキルでは複製しない。

## 1. 作業開始時に参照する

1. vault の `main` を `git pull --ff-only` で最新化する。ローカルにない場合は clone する。
2. 作業対象のリポジトリ名、技術、キーワードで `notes/` と `inbox/` を検索し、関連ノートがあれば読んでから作業する。
3. ノートの内容が現在のコードや設定と矛盾する場合は、現物を正とし、後述の手順でノートを修正する。

## 2. 残す知識を選ぶ

作業の区切りや完了時に、得た情報を次の基準で選別する。

残すもの:

- 別の作業・別のリポジトリでも再利用できる知識
- 調査に時間がかかった事実、ハマりどころと解決策、非自明な挙動
- 設計・運用判断の理由（なぜそうしたか）

残さないもの:

- vault の `README.md` の「書かないもの」に該当する情報
- その作業の中だけで意味を持つ経緯や一時的な状態
- 推測のまま検証していない内容（残す場合は「未検証」と明記して `inbox/` に置く）

残すものがなければ、何もしないで終えてよい。

## 3. 既存ノートを育てる

1. 新規作成の前に、同じトピックのノートを `notes/` と `inbox/` から検索する。
2. 該当ノートがあれば、そのノートへ追記・修正する。
   - 既存の記述と重複する内容は書き足さず、より正確・具体的な表現に置き換える。
   - 古くなった記述は削除または修正し、矛盾を残さない。
   - frontmatter の `updated` と `sources` を更新する。
3. 該当ノートがなければ、vault の `README.md` の記法に従って `notes/` に新規作成する。出典や文脈が不足する断片は `inbox/` に置く。
4. 関連ノートへ `[[ノート名]]` で双方向にリンクする。
5. 触れたノートの周辺で、重複ノートや `inbox/` の整理できる断片を見つけたら統合する。

## 4. 反映する

1. `git status --short` で、意図したノート以外の変更がないことを確認する。他の変更は巻き込まない。
2. `git diff` で秘密情報や社外秘の情報が含まれていないことを確認する。
3. 日本語のコミットメッセージ（例: `Helm values の上書き順序を追記`）でコミットし、`git push origin main` で反映する。push が拒否された場合は `git pull --rebase` して再試行し、衝突した場合は両方の内容を統合する。force push はしない。

## 5. 完了条件

- 残すべき知識が既存ノートへの統合または新規ノートとして `main` に反映されている。
- 同じトピックのノートが重複していない。
- 秘密情報や作業固有の経緯を含めていない。
- ユーザーへの最終報告で、追加・更新したノート名を伝えている。
