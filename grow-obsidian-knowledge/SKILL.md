# Grow Obsidian Knowledge

## 目的

作業中に得たコンテキストを、次の作業で再利用できる知識として Obsidian vault に蓄積し、手順として固まった知識は Agent Skill へ昇格させる。ノートを増やすことではなく、既存ノートを更新・統合して知識を育てることを優先する。

- vault の正本は GitHub の `taiseiishiyama00/obsidian-knowledge`、ローカルは通常 `$HOME/repos/obsidian-knowledge`。
- vault の構成、ノートの記法、書かないものは vault の `README.md` を正本とし、このスキルでは複製しない。
- vault は「事実・挙動・判断の理由」、Agent Skill は「繰り返し実行する手順・判断基準」を所有する。同じ内容を両方に書かない。

## 1. 作業開始時に参照する

1. vault を最新化する。ローカルにない場合は `$HOME/repos/obsidian-knowledge` へ clone する（private リポジトリのため認証が必要）。ある場合は `git status --short` で未コミット変更がないことを確認してから `git pull --ff-only` する。未コミット変更や fast-forward できない状態は勝手に破棄せず、原因を確認してから進める。
2. 作業対象のリポジトリ名、技術、キーワードで `notes/` と `inbox/` を検索する。ファイル名だけでなく、本文、frontmatter の `tags` と `sources` も検索対象にする。関連ノートがあれば読んでから作業する。
3. ノートの内容が現在のコードや設定と矛盾する場合は、現物を正とし、後述の手順でノートを修正する。

## 2. 残す知識を選ぶ

作業の区切りや完了時に、得た情報を次の基準で選別する。

残すもの:

- 別の作業・別のリポジトリでも再利用できる知識
- 調査に時間がかかった事実、ハマりどころと解決策、非自明な挙動
- 設計・運用判断の理由（なぜそうしたか）

残さないもの:

- vault の `README.md` の「書かないもの」に該当する情報
- その作業の中だけで意味を持つ経緯や一時的な状態
- 既存の Agent Skill がすでに所有している手順や判断基準（スキル側を更新すべき内容は手順 4 に従う）
- 推測のまま検証していない内容（残す場合は「未検証」と明記して `inbox/` に置く）

残すものがなければ、何もしないで終えてよい。

## 3. 既存ノートを育てる

1. 新規作成の前に、同じトピックのノートを `notes/` と `inbox/` から検索する。
2. 該当ノートがあれば、そのノートへ追記・修正する。
   - 既存の記述と重複する内容は書き足さず、より正確・具体的な表現に置き換える。
   - 古くなった記述は削除または修正し、矛盾を残さない。
   - frontmatter の `updated` と `sources` を更新する。
3. 該当ノートがなければ、vault の `README.md` の記法に従って `notes/` に新規作成する。出典や文脈が不足する断片は `inbox/` に置く。
4. 関連ノートへ `[[ノート名]]` で双方向にリンクする。ノート名を変更した場合は、vault 全体の旧名へのリンクを付け替える。
5. 触れたノートの周辺で、重複ノートや `inbox/` の整理できる断片を見つけたら統合する。

## 4. スキルへ昇格する

ノートが「次も同じ順序で実行する手順」や「毎回適用する判断基準」に育ったら、Agent Skill へ昇格させてスキルを進化させる。

1. 昇格の条件を確認する。次をすべて満たす場合だけ昇格する。
   - 2 つ目の作業・リポジトリでも同じ責務と条件で使えると確認できている（1 回の作業だけで一般化しない）。
   - 事実の羅列ではなく、発火条件と実行手順として書ける。
   - 検証済みで、「未検証」の記述を含まない。
2. `$HOME/repos/agent-skills` の既存スキルから同じ責務のスキルを探す。あれば既存スキルへ追記し、なければ新規スキルを作る。スキルの追加・更新は `update-agent-skills` スキルの手順に従う。
3. 昇格した手順はノートから削除し、ノートには事実・理由・背景だけを残して、手順の所有先としてスキル名を記載する。スキル側にノートの内容を丸ごと複製しない。
4. 昇格の条件を満たさない場合は、ノートとして育て続ける。

## 5. 反映する

1. `git status --short` で、意図したノート以外の変更がないことを確認する。他の変更は巻き込まない。
2. `git diff` で秘密情報や社外秘の情報が含まれていないことを確認する。
3. 日本語のコミットメッセージ（例: `Helm values の上書き順序を追記`）でコミットし、`git push origin main` で反映する。push が拒否された場合は `git pull --rebase` して再試行し、衝突した場合は両方の内容を統合する。force push はしない。
4. スキルへ昇格した場合は、vault とスキルの両方の反映を確認してから完了とする。

## 6. 棚卸する

定期実行（1 日 1 回程度）またはユーザーが「棚卸して」と依頼したときに、vault 全体を精査して不要な情報を削除し、昇格候補を見つける。削除した内容は Git 履歴から復元できるため、残す理由のない情報は削除してよい。

1. vault の `main` を最新化し、`notes/` と `inbox/` の全ノートを読む。ノートが 1 つもなければ、何もしないで終えてよい。
2. 次の観点で精査し、修正または削除する。
   - 重複: 同じトピックのノート、または同じ事実を複数ノートに書いているもの。1 つのノートへ統合し、他方は削除してリンクを付け替える。
   - 古い情報: `sources` の現物（リポジトリ、ドキュメント）を参照できる場合は内容を照合し、矛盾する記述を修正または削除する。参照できない場合は、更新日が古いことだけを理由に削除しない。
   - `inbox/` の滞留: 作成日は frontmatter に持たないため、`git log --diff-filter=A --follow --format=%as -- <path>` の最も古い日付で判断する。作成から 14 日以上経過した断片は、`notes/` へ統合するか、出典や文脈が揃わなければ削除する。
   - スキルとの重複: `$HOME/repos/agent-skills` の各 `SKILL.md` と照合し、スキルが所有する手順をノートに書いている場合はノートから削除してスキル名を記載する。
   - 昇格候補: 手順 4 の条件を満たすノートがあれば昇格する。
   - vault の `README.md` の「書かないもの」に該当する記述: 削除する。
   - リンク切れや空になったノート: 修正または削除する。存在しないノートへのリンクは README で許容されているため、リンク先ノートが削除・改名された場合だけをリンク切れとして扱う。
3. 手順 5 に従って反映する。コミットメッセージは `知識の棚卸` とし、本文に統合・削除・昇格したノート名と理由を列挙する。変更がなければコミットしない。

## 7. 完了条件

- 残すべき知識が既存ノートへの統合または新規ノートとして `main` に反映されている。
- 同じトピックのノートが重複しておらず、ノートとスキルで同じ手順を重複して持っていない。
- 昇格条件を満たした知識が Agent Skill に反映されている。
- 秘密情報や作業固有の経緯を含めていない。
- ユーザーへの最終報告で、追加・更新・削除したノート名と、昇格・更新したスキル名を伝えている。
