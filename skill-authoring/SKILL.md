# スキルの作成

## 目的

スキルを、長く変わらない骨格と、使うたびに項目が増える育てていく部分に分けて作る。寿命の違うものを同じファイルに混ぜると、追記のたびに骨格のファイルが書き換わり、どこを変えてよいのかが分からなくなるためである。

## 構成

```text
<skill-name>/
  SKILL.md
  agents/
    openai.yaml
  references/
    <育てていく部分>.md
```

- `SKILL.md`: 骨格を書く。先頭に YAML frontmatter を置く。
  - `name`: ディレクトリ名と同じにする。小文字の英数字とハイフンだけを使う。
  - `description`: 何をするスキルかと、どんな依頼で使うかを書く。発火の判断はこの欄だけで行われるため、依頼の言い方の例も入れる。
- `agents/openai.yaml`: Codex の表示用に、`interface` の `display_name`、`short_description`、`default_prompt` を書く。
- `references/`: 育てていく部分のファイルを置く。

## 骨格と育てていく部分

| | 骨格 | 育てていく部分 |
|---|---|---|
| 中身 | 目的、手順、フェーズ、判断の基準、出力の書式 | 観点表、チェックリスト、用語集、事例など、使うたびに項目が増える一覧 |
| 置き場所 | `SKILL.md` | `references/` の別ファイル |
| 変わるとき | 進め方そのものを変えるとき | スキルを使う中で、新しい項目が採用されたとき |

- 育てていく部分は別ファイルにし、`SKILL.md` からリンクする。`SKILL.md` には項目を書き写さない。
- 育てていく部分のファイルの冒頭に、何の正本か、育てていく部分であること、追記の手順が `SKILL.md` のどこにあるかを書く。
- 育てていく部分は、はじめは少なくてよい。使いながら足す。

## 育てる手順を書く

育てていく部分を持つスキルの `SKILL.md` には、使う中で自分を育てる手順を書く。手順には次を含める。

1. 追記するとき: どの時点で新しい項目が採用されたとみなすか（例: フェーズの結果に「次」と入力されたとき）。
2. 追記する場所: どのファイルの、どの位置に足すか。
3. 反映のしかた: この `SKILL.md` がある Git リポジトリで既定ブランチを pull し、育てていく部分のファイルだけをコミットして push する。スキルを使っている作業中のリポジトリのブランチには含めない。
4. 反映できないとき: リポジトリでない、未コミットの変更がある、push が拒否されたなどの場合は、追記する内容を利用者に報告して、作業を続ける。

## 確認

作成や修正を終えたら、次を確かめる。

- `name` とディレクトリ名が一致し、frontmatter が YAML として読める。
- 育てていく部分の項目が `SKILL.md` に書かれていない。
- `SKILL.md` から、育てていく部分のファイルへのリンクが切れていない。
