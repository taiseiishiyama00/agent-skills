# フレームワーク・観点表

doc-creation のフェーズ 2 で材料を集めて不足情報を聞き出すための、フレームワークと観点の正本である。使うたびに育てていく部分であり、追記の手順は `SKILL.md` の「フレームワーク表を育てる」に従う。

## 共通フレームワーク（報告系）

すべての報告資料で最初に揃える基本軸である。資料種別ごとの観点とあわせて使う。

| 軸 | 確認すること |
|---|---|
| 前提・宛先 | 誰への報告か（役割・前提知識・関心事）、利用場面（口頭発表／配布・読み物、持ち時間・分量）、相手に求める反応（状況共有／判断・承認／相談） |
| 結論ファースト | 全体を通して一番伝えたい結論は何か（1〜2 文で言える状態にする） |
| What（事実） | 実際に起きたこと、実施したこと、計測した数値、一次情報などの客観的な根拠（対象期間・条件を含む） |
| So What（解釈） | 事実から何が言えるか、目標や期待に対して順調か課題があるか（事実と混ぜずに分けて扱う） |
| Now What（次の一手） | 次に誰が・何を・いつまでにするか、聞き手に依頼する判断やアクション |

## 資料種別ごとの観点表

現時点では報告系を中心に定義している。提案・企画、技術解説、マニュアルなど他の用途や新しい報告種別を扱う場合は、使いながら行や観点を追加して育てる。

| 資料の種別 | 骨格の流れ | 集めるべき材料の観点 |
|---|---|---|
| 進捗・定例報告 | 結論サマリ → 計画対比 → 課題・リスク → 次のアクション・相談 | 対象期間と範囲、全体の状態（順調／遅れ／要注意）と判断基準、計画と実績の差（完了・未完了・数値）、遅れや課題の原因・影響範囲、挽回策とネクストアクション（担当・期限）、聞き手への判断・相談事項 |
| 調査・検証・分析報告 | 背景・問い → 結論・推奨 → 検証条件・方法 → 事実データ → 考察 → 限界と次 | 調査の目的と解きたい問い、結論と推奨案（比較した選択肢と選んだ理由）、検証条件・対象データ・前提制約、実測値や一次情報の根拠、事実から導いた考察と懸念点、未検証事項・限界と次のアクション |
| 障害・振り返り報告 | 概要・影響 → 復旧状況 → 時系列 → 原因 → 対策 | 発生事象と影響範囲（対象・件数・期間）、現在の状態（復旧済み／調査中）、検知〜切り分け〜復旧の時系列、直接原因と根本原因（仕組みの穴）、暫定対応と恒久対策（担当・期限） |
| 施策・完了報告 | 目的・当初ゴール → 成果 → 要因・学び → 残課題・引き継ぎ | 着手時の背景と目標値、達成した成果（定量・定性）と目標とのギャップ、成功要因・つまずきと再利用できる学び、未解決の課題・今後の運用体制と次の打ち手 |
