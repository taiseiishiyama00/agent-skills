# PR レビュー評価観点表

このファイルは `pr-review` スキル（[../SKILL.md](../SKILL.md)）の評価観点の正本である。
使うたびに新しい観点や典型的なチェック項目を追加して育てていく部分であり、追記の手順は [../SKILL.md](../SKILL.md) の「観点表を育てる手順」に従う。

## 優先順位

設計の整合性を最優先する。細かいバグや好みの指摘は省き、バグは致命的なものだけを拾う。

## 1. 設計からの逸脱・不要な実装

- 仕様書やチケットの対応方針から外れた独自機能・独自バリデーションがねじ込まれていないか。
- 今回の要件に不要な責務追加や公開 API 変更（`PublicAPI.Unshipped.txt` 等）が発生していないか。
- 機能・プラグインの配置先（必須基盤パッケージ vs 拡張・汎用パッケージ等）が責務と合っているか。
- 共通コーディングルール（[../../coding-rules/references/prohibitions.md](../../coding-rules/references/prohibitions.md)）に違反していないか。

## 2. 抜け漏れ

- 新しい型・種別（enum 等）を追加したとき、同種の既存処理（`switch` 分岐、ジェネレーター、ファクトリ、バリデーター、シリアライザー、UI 選択肢、配列型などの対になる定義）に漏れがないか。
- 変更前のコメントアウト箇所や TODO が未対応のまま残っていないか。

## 3. 無駄

- 既存の汎用処理（値型の既定値生成、標準デシリアライザー等）で既にカバーされている冗長な分岐がないか。
- 未使用のプロジェクト参照（`.csproj`）、using、メソッド、引数、テストがないか。
- 同じ処理や同じ探索の二重実装・二重走査がないか。

## 4. 既存コードとの不揃い

- 他の型や既存機能と、変換順序・エラー処理・UI コンポーネントの使い方・命名が揃っているか。
- 内部実行時型の統一ルールと、ジェネレーターやマッパーの対応表が矛盾していないか。

## 5. 無理のある実装

- 既存の汎用パス（例: `JsonElement` の標準デシリアライズ）の手前に特定型のための割り込みを入れ、他型への副作用リスクを生んでいないか。
- 暗黙の型前提（ジェネリック型引数と実際の利用型の不一致など）に依存していないか。

## 6. 致命的なバグ

- コンパイルエラー・ソースジェネレーターの診断エラー（例: 未対応型エラー）になる経路が残っていないか。
- 実行時例外（未対応の分岐、固定長コレクションへの破壊的変更、null 参照など）やデータ破損・不整合が起きないか。
